# 가벼운 주소 기준 DB: 원본 파르케 + 단일 목록 DB

이 패키지는 **완성된 작은 DB**와 사용·재생성 코드를 포함합니다. 2023·2024·2025년이 작은 DB 하나에 함께 들어 있습니다. 기존의 약 1GB짜리 연도별 DB는 사용하지 않습니다. 기존 파일을 삭제하거나 수정하지 않았습니다.

## 시작

1. ZIP을 풀고 `use_address_lite.ipynb`를 엽니다.
2. `SOURCE_DIR` 한 곳만 기존 원본 파르케 3개가 있는 폴더로 지정합니다.
3. 순서대로 실행합니다. 원본을 옮기거나 파일을 합칠 필요는 없습니다.

필요 파일명: `RAW_DATA_2023.parquet`, `RAW_DATA_2024.parquet`, `RAW_DATA_2025.parquet`.
원본 파르케는 패키지에 중복 포함하지 않았습니다. 이미 보유한 원본을 사용합니다.

설치: `%pip install duckdb pandas`. 생성·검증한 DuckDB 버전은 validation.json에 기록했습니다.

## 저장 역할

|파일|내용|
|---|---|
|address_catalog.duckdb|지역·도로명 목록, 코드 대응, 부모자식 계층, 기준연도, 원본 메타데이터|
|기존 원본 Parquet 3개|모든 주소행, 지번·건물번호, 건물명, 원본 코드와 기타 원본 컬럼|
|address_lite.py|목록 DB 생성, 후보 조회, 연도별 결과 취합|
|use_address_lite.ipynb|사용 예와 선택적 재생성|
|validation.json|실제 원본/기존 DB와의 대조 결과, 크기|

DB에 주소 전체 테이블이나 건물·지번 번호 인덱스를 복사하지 않았습니다. DuckDB가 파르케에서 필터 조건에 맞는 행을 읽습니다. 지역 이름·도로명은 작은 DB에서 후보 코드를 찾고, 번호 조건은 원본 파르케에 적용합니다. 파르케 파일을 없애면 상세 후보 조회를 할 수 없습니다.

## 유지한 구조

- `sido → sigungu → emd → ri`: 법정 지역 단계, 이름과 코드 구간
- `sigungu → road_catalog`: 도로명과 2/3/1/6자리 코드 구간
- `road_table`: 시도명·시군구명·도로명을 함께 보여주는 뷰
- `region_hierarchy`, `sigungu_hierarchy_links`: 고양시 → 덕양구 같은 시/구 분리. 같은 형태인 다른 시·구에도 적용
- `legal_regions`: 법정 지역의 원본 이름과 전체코드
- `admin_sido`, `admin_sigungu`, `admin_emd`, `administrative_units`: 행정구역분류의 원본 관측 명칭과 코드
- `legal_road_links`, `legal_admin_links`, `region_admin_links`: 체계 간 연결
- `sources`: 기준연도, 파일명, 크기, SHA-256, 원본행수, 기준연월, 일련번호 고유성
- `region_counts`: 지역별 원본행수 검산
- `metadata`: 코드 자리 구성과 주의사항

연도별 연결은 `기준연도 + 코드/노드ID`를 함께 사용합니다. 원본의 같은 이름이 연도마다 같은 관할을 보장하지는 않습니다. 시/구 분리 과정에서 중간 시의 공식 코드를 추정해 넣지 않았습니다.

```python
from address_lite import LiteAddressDB
engine = LiteAddressDB('address_catalog.duckdb', '/원본파르케폴더')
regions = engine.find_regions(sido='경기도', city='고양시', district='덕양구')
# 단일 연도: 실제 코드/번호로 검색
# result = engine.road(2025, 실제12자리도로명코드, 실제본번, sub=0)
# result = engine.lot(2025, 실제10자리법정동코드, 실제본번, sub=0)
# 연도를 모르면 이름을 연도별로 해석하고 원본을 각각 조회
# result = engine.lot_by_region(sido='...', sigungu='...', emd='...', main=실제본번)
# result = engine.road_by_name(name='...', main=실제본번, sido='...', sigungu='...')
engine.close()
```

`candidate_count`는 조건에 맞는 전체 원본행수입니다. `candidates`에는 화면 표시 limit를 적용하지만 `code_combinations`는 전체 후보에서 구합니다. 같은 원본행은 `(기준연도, 일련번호)`로 찾습니다. 이 키는 건물관리번호나 연도 간 영구 식별자가 아닙니다.

부번 `None`은 부번 조건을 생략하고 0은 실제 0을 검색합니다. 대지구분을 생략하면 모든 원본 대지구분을 후보로 남깁니다. 원본에 없는 정보나 번호를 임의로 채우지 않습니다.

## 판정 범위와 자료 버전

- 후보 상태는 자동 확정이 아닙니다. 코드 조합이 하나여도 주소가 여러 개일 수 있습니다.
- 연도별 결과는 입력 작성연도를 알려주지 않습니다. 원래 주소 연도는 None으로 유지합니다.
- 이번 행정동 제외 파일럿에 맞춰 기본 코드 비교는 법정동·도로명만 사용합니다. 행정구역분류코드는 보존하며 명시적으로 `include_admin=True`를 주면 비교에 포함합니다.
- 행정구역분류의 명칭은 원본 관측 연결이며 공식 명칭표 검증 전입니다.
- 오타·약칭·띄어쓰기 없는 주소 파싱, LLM, 변경 이력, 사람 검토는 별도 모듈입니다.
- 지하구분·건물동·층·호는 원본에 없으므로 생성하지 않았습니다.
- 초기화할 때 원본 파일 존재·크기를 확인합니다. `verify_hash=True`로 SHA-256도 확인할 수 있습니다. 같은 크기의 다른 파일까지 막으려면 해시 검사를 사용하세요.
- 원본이 교체되면 작은 DB도 새로 생성하세요. 파일을 다시 만들 때 기존 DB를 덮어쓰지 않습니다.

## 크기와 검산

작은 DB: 59,518,976바이트. 원본 3개 합계: 261,297,435바이트.

새 구성 합계: 59,518,976 + 261,297,435 = 320,816,411바이트. 기존 연도별 DB 3개 합계는 3,182,989,312바이트였습니다. MB는 바이트/1,000,000, GB는 바이트/1,000,000,000입니다.

원본 해시, 연도별 행수 합계, 시/구 분리, 부모키 연결, 실제 지번·도로명 조건의 기존 DB 결과와 대조를 검증했습니다. 검증 표본의 일치는 전체 비정형 정제 정확도를 뜻하지 않습니다. 작은 DB에는 원본 주소가 없기 때문에 원본 파르케 행수를 메타데이터 및 지역별 합계로 대조합니다.
