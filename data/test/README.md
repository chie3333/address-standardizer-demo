# 주소 매칭 오류 검증 데이터셋

`RAW_DATA_2025.parquet`에서 전국 17개 시·도의 기준 주소를 골라 테스트 입력 1,000건을 만들었습니다. 정상 주소 134건과 오류·경계 사례 866건입니다. 기존 오류 목록 1~7번의 90개 유형은 주소 입력과 단계별 검증 사례에서 모두 찾을 수 있습니다.

## 실행 순서

1. [주소_입력_1000.csv](주소_입력_1000.csv)를 주소 정제 화면에 올리고 주소 열은 `raw_address`, ID 열은 `address_id`를 선택합니다. CSV에는 실제 줄바꿈·탭이 들어간 주소와 공백만 있는 주소가 포함되어 있습니다.
2. [주소_정답_1000.json](주소_정답_1000.json)의 `cases`에서 같은 `address_id`를 찾아 실행 결과를 비교합니다. `expected_status`는 기대 판정이며, `check`는 해당 입력에서 확인할 동작입니다.
3. [단계별_검증_사례.json](단계별_검증_사례.json)의 `coverage`에서 오류 유형별 입력 건수를 확인할 수 있습니다. `fixtures`에는 LLM 응답, DB 조회 조건, 후보 목록 또는 결과 화면에 넘길 데이터와 각각의 기대 결과가 들어 있습니다. 주소 업로드 뒤에도 JSON·ID 오류, 후보 제한·캐시, 화면 집계는 해당 단계에 검증 데이터를 넣어 확인합니다.

## 기대 판정

| 기대 상태 | 건수 | 확인할 결과 |
| --- | ---: | --- |
| `resolved` | 666 | 표준 도로명주소와 도로명코드·법정동코드·행정구역분류코드가 같은 기준 행에서 일치 |
| `held` | 255 | 복수 후보, 입력 정보 부족, 오타 교정 검토, 지하 여부 미확인 등으로 보류 |
| `no_match` | 53 | 입력 조건을 함께 만족하는 2025년 기준 행이 없음 |
| `address_only` | 13 | 기본주소는 확인되며 행정구역분류코드가 결측 |
| `excluded` | 13 | 공백만 있거나 숫자만 있는 입력으로 전처리에서 제외 |

- `source_rows`에는 변형 전 주소, 구성요소, 기준자료의 일련번호가 있습니다. 보류·불일치 사례에서 원본 주소는 변형의 출처입니다. 채점에는 `expected_status`, `check`, 그리고 확정 건의 `expected_standardization`을 사용합니다.
- `reference_check`의 `matched_rows`는 기준 행 수, `distinct_outputs`는 서로 다른 표준 주소·코드 조합 수입니다. `candidate_examples`는 확인용 예시이며 복수 후보는 최대 5개를 담았습니다. 오타 사례의 `literal_rows`는 교정 전 표기에 대한 일치 행 수입니다.
- 지하 표기는 2025년 기준자료에 지하 여부 필드가 없어 기본주소 후보까지만 확인할 수 있습니다. 기준연도 검증 사례 12건은 2024년 자료에서 확인했고, 동일 조건을 2025년 자료에 적용하면 일치 행이 0건입니다.
- 이 데이터셋은 기준 DB 대조 결과와 기대 동작을 담고 있습니다. 실제 LLM을 연결한 1,000건 전체 실행의 성능은 별도로 측정해야 합니다.
